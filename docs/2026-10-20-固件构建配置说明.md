# 固件构建配置说明

本仓库的 `24.10.6` 分支在 ImmortalWrt 24.10.6 基础上，为 MediaTek Filogic MT7981 的两个机型各维护一份独立 seed 配置。两份配置都只选择单设备 profile，不使用 `CONFIG_TARGET_MULTI_PROFILE`；`master`、`25.12.2` 分支不包含这两份配置。

## 配置与机型

| 配置文件 | 机型 | 应用差异 |
| --- | --- | --- |
| `rax3000m.config` | CMCC RAX3000M | 带 USB 3.0，预装 diskman、hd-idle、samba4 |
| `ax3000t.config` | Xiaomi Mi Router AX3000T（OpenWrt U-Boot layout） | 无 USB 接口，不含上述存储应用 |

拆分后每份配置只带入对应机型的 profile 包，避免 RAX3000M 的 `kmod-usb3`、`automount`、`f2fsck`、`mkf2fs` 等进入 AX3000T 固件。

## 构建

```bash
./scripts/feeds update -a
./scripts/feeds install -a

cp rax3000m.config .config    # 或 cp ax3000t.config .config
make defconfig
make download -j8
make -j$(nproc) V=s
```

产物位于 `bin/targets/mediatek/filogic/`。切换机型时重新执行 `cp <配置> .config && make defconfig`。

两份配置默认开启 ccache（`CONFIG_CCACHE=y`），缓存位于源码根目录 `.ccache`；首次构建不会加速，重复构建或切换机型时生效。

## 维护约定

- 只手动维护“目标设备 / 镜像 / 应用 / 编译工具”四类选项；内核、BusyBox、依赖包、工具链由 `make defconfig` 自动补齐。
- 所有应用及其专属编译选项集中在配置文件的“四、应用及其依赖”一节，应用专属开关紧跟所属应用。
- 新增应用后只提交 seed 配置，不要把 menuconfig 全量输出直接提交。
- 第三方 feed（如 `lucky`）由编译仓库（[ImmortalWrt-firmware-build](https://github.com/DenzelVincent/ImmortalWrt-firmware-build)）统一追加，源码仓库的 `feeds.conf.default` 只保留默认 feed。
- 应用的中文翻译包必须显式写在该应用下方（`CONFIG_PACKAGE_luci-i18n-<应用>-zh-cn=y`；OpenClash 主包已内置翻译）；`CONFIG_LUCI_LANG_zh_Hans` 只选择基础翻译，不会自动带入应用翻译。
- `=y` 表示编译并预装进固件；`=m` 表示只编译 ipk、不预装，刷机后需手动安装。
- 单设备构建必须保留 `# CONFIG_TARGET_MULTI_PROFILE is not set`，并使用 `CONFIG_TARGET_mediatek_filogic_DEVICE_<机型>=y`。
